# Configuration TUI Guide

## Quick Start

Launch the interactive configuration editor:

```bash
astrolabe config edit
```

## Features

The configuration TUI provides an interactive interface for setting up Astrolabe's connection to your backend server.

### Fields

1. **API URL** - The base URL of your backend server
   - Example: `https://qa.yourcompany.com`
   - Used for all API calls (create run, presigned URLs, confirm uploads)

2. **Project ID** - The project identifier for your uploads
   - Example: `project-123`
   - Links uploaded runs to a specific project in your QA application

3. **Auth Token** - API authentication token
   - Masked by default with `•` characters for security
   - Press `Ctrl+T` to toggle visibility while focused on this field
   - Used in `Authorization: Bearer <token>` header

4. **Offline Cache** - Local directory for storing run artifacts
   - Default: `~/.astrolabe/runs`
   - This is where captured data is stored before upload

5. **Max Retries** - Number of upload retry attempts
   - Default: `3`
   - Used when network errors occur during upload

## Keyboard Controls

- `↑` / `↓` or `Tab` / `Shift+Tab` - Navigate between fields
- `Enter` - Move to next field
- `Ctrl+T` - Toggle auth token visibility (when focused on token field)
- `Ctrl+S` - Save configuration
- `Esc` or `Ctrl+C` - Exit without saving (if no changes made)

## Configuration File

Settings are saved to `~/.astrolabe/connection.yml`:

```yaml
# Astrolabe Connection Configuration
# Backend server connection and upload settings
# Generated by astrolabe config edit

api_url: "https://qa.yourcompany.com"
project_id: "project-123"
auth_token: "your-token-here"
offline_cache: "/home/user/.astrolabe/runs"

upload:
  max_retries: 3
```

## Alternative Methods

### Command-line

Set individual values:
```bash
astrolabe config set api_url "https://qa.yourcompany.com"
astrolabe config set project_id "project-123"
astrolabe config set auth_token "your-token"
```

Get values:
```bash
astrolabe config get api_url
```

### Environment Variables

Override config file settings:
```bash
export ASTROLABE_API_URL="https://qa.yourcompany.com"
export ASTROLABE_PROJECT_ID="project-123"
export ASTROLABE_AUTH_TOKEN="your-token"
```

Environment variables take precedence over the config file.

## Workflow

1. **First-time setup**:
   ```bash
   astrolabe config edit
   # Fill in API URL, project ID, and auth token
   # Press Ctrl+S to save
   ```

2. **Verify configuration**:
   ```bash
   astrolabe config get api_url
   ```

3. **Test upload** (after capturing data):
   ```bash
   astrolabe upload
   ```

## Security Notes

- The auth token is stored in plain text in `~/.astrolabe/connection.yml`
- Set file permissions to `0600` (owner read/write only) for better security
- Consider using environment variables in CI/CD environments
- Never commit `connection.yml` to version control

## Troubleshooting

### "Config file not found"

The TUI will create `~/.astrolabe/connection.yml` when you save. If you want it in a different location, create the file manually and set `--config` flag:

```bash
astrolabe --config /path/to/connection.yml config edit
```

### "Permission denied"

Check directory permissions:
```bash
ls -la ~/.astrolabe/connection.yml
```

If needed, fix permissions:
```bash
chmod 600 ~/.astrolabe/connection.yml
```

### "Invalid max_retries value"

Max retries must be a number (integer). The TUI will show an error if you enter non-numeric values.
