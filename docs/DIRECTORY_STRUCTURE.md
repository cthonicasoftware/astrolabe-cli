# Astrolabe Directory Structure

## Overview

All Astrolabe configuration and data is stored in `~/.astrolabe/`:

```
~/.astrolabe/
├── connection.yml       # Backend connection & upload settings
├── metadata.json        # Run metadata defaults
└── runs/               # Offline cache for captured runs
    └── <run-id>/
        ├── manifest.json
        ├── data.jsonl
        └── upload_state.json
```

## Configuration Files

### connection.yml

**Purpose**: Backend server connection and upload configuration

**Location**: `~/.astrolabe/connection.yml`

**Content**:
```yaml
# Astrolabe Connection Configuration
# Backend server connection and upload settings
# Generated by astrolabe config edit

api_url: "https://qa.yourcompany.com"
project_id: "project-123"
auth_token: "your-api-token-here"
offline_cache: "/home/user/.astrolabe/runs"

upload:
  max_retries: 3
```

**Edit via**:
- Interactive TUI: `astrolabe config edit`
- Command-line: `astrolabe config set api_url "https://..."`
- Manual: Edit the file directly

**Environment overrides**:
- `ASTROLABE_API_URL`
- `ASTROLABE_PROJECT_ID`
- `ASTROLABE_AUTH_TOKEN`

### metadata.json

**Purpose**: Default metadata for all captures

**Location**: `~/.astrolabe/metadata.json`

**Content**:
```json
{
  "operator": "nate",
  "location": "bench-1",
  "device": {
    "id": "device-001",
    "serial": "SN12345",
    "firmware": "v1.2.3",
    "firmware_hash": "abc123",
    "hardware_version": "rev-A"
  },
  "test": {
    "plan": "smoke-test",
    "variant": "standard",
    "run": ""
  },
  "tags": ["automated", "ci"],
  "attributes": {
    "environment": "lab"
  }
}
```

**Edit via**:
- Interactive TUI: Select "Configure Metadata" from `astrolabe tui`
- Command-line: `astrolabe config set operator "nate"`

## Run Cache

**Purpose**: Local storage for captured runs before upload

**Location**: `~/.astrolabe/runs/<run-id>/`

Each run directory contains:

### manifest.json

Complete run metadata including device info, test plan, timestamps, and source details.

### data.jsonl

Newline-delimited JSON records captured from the source:
```jsonl
{"ts":"2024-01-15T10:00:00Z","seq":1,"type":"measurement","payload":{"voltage":3.3}}
{"ts":"2024-01-15T10:00:01Z","seq":2,"type":"measurement","payload":{"voltage":3.2}}
```

### upload_state.json

Upload tracking information:
```json
{
  "status": "succeeded",
  "attempts": 2,
  "last_error": "",
  "last_attempt": "2024-01-15T10:30:00Z",
  "completed_at": "2024-01-15T10:30:05Z",
  "remote_run_id": "run-67890"
}
```

**Status values**:
- `pending` - Never uploaded
- `queued` - Scheduled for upload
- `in_flight` - Currently uploading
- `succeeded` - Upload complete
- `failed` - Upload failed after retries

## Directory Management

### Automatic Creation

Astrolabe automatically creates these directories when needed:
- `~/.astrolabe/` - Created on first config or metadata save
- `~/.astrolabe/runs/` - Created on first capture

### Manual Cleanup

Remove old captured runs:
```bash
# List runs
ls ~/.astrolabe/runs/

# Remove a specific run
rm -rf ~/.astrolabe/runs/<run-id>

# Remove all runs (careful!)
rm -rf ~/.astrolabe/runs/*
```

### Backup

To backup your configuration:
```bash
# Backup both config files
cp ~/.astrolabe/connection.yml ~/astrolabe-connection-backup.yml
cp ~/.astrolabe/metadata.json ~/astrolabe-metadata-backup.json

# Or backup entire directory
tar -czf astrolabe-backup.tar.gz ~/.astrolabe/
```

### Migration from Old Config

If you have an old `~/.astrolabe.yml` in your home directory, migrate it:

```bash
# Create the directory if needed
mkdir -p ~/.astrolabe

# Move and rename the file
mv ~/.astrolabe.yml ~/.astrolabe/connection.yml
```

## Permissions

Recommended permissions for security:

```bash
# Connection file contains auth tokens
chmod 600 ~/.astrolabe/connection.yml

# Directory
chmod 755 ~/.astrolabe/

# Metadata file
chmod 644 ~/.astrolabe/metadata.json

# Runs directory
chmod 755 ~/.astrolabe/runs/
```

## Troubleshooting

### "Permission denied" when saving config

```bash
# Fix directory permissions
chmod 755 ~/.astrolabe/

# Fix file permissions
chmod 600 ~/.astrolabe/connection.yml
```

### Config file in wrong location

Check which config file is being used:
```bash
astrolabe config get api_url
# If empty, config file may not exist

# Check viper is loading the right file
astrolabe --config ~/.astrolabe/connection.yml config get api_url
```

### Disk space issues

Check run cache size:
```bash
du -sh ~/.astrolabe/runs/
```

Upload pending runs to free space:
```bash
astrolabe upload
```
